# Plán: Sent fix + synchronizace + Profil (Jméno/Příjmení/Telefon) — 0.0.31

**Stav:** čeká na schválení
**Návratový bod:** `Latest-Dev` HEAD `4a95ac0` (0.0.30, po FF merge)
**Cílová verze:** 0.0.31 (MARKETING_VERSION 0.0.31, CURRENT_PROJECT_VERSION 30)
**Rozsah:** iOS klient + minimální backend podpora (bez změn web frontendu)

## Cíl

1. **Sent zobrazuje odeslané e-maily** v iOS.
2. **Synchronizace/příjem e-mailů funguje spolehlivě** (sync při startu, bez race).
3. **Profil:** v Profile page lze nastavit Jméno, Příjmení a telefonní číslo; jméno se použije v From hlavičce při odesílání.

## Diagnóza (fakta z kódu)

### A. Sent je prázdný — příčina
- Backend ukládá odeslané jako `direction='outbound', folder='sent'` (`src/openmail/services/resend_service.py:219-234`).
- Čtení vždy filtruje `direction` + `folder`, default direction je `inbound` (`src/openmail/routes/emails.py:20-45`, `email_service.py:78-105`).
- **iOS nikdy neposílá `direction`** (`ios/openMail/API/APIClient.swift:403-426` parametr neexistuje; `InboxView.swift:435-444` posílá jen `folder=sent`) → dotaz `inbound+sent` = 0 řádků.
- Web funguje, protože posílá `direction=outbound` pro sent (`static/js/app.js:78-82`).

### B. Špatný sync/příjem — příčiny
- iOS syncuje **jen na pull-to-refresh** jako `Task.detached` bez čekání a `fetch()` listu běží hned paralelně → race, nové maily se typicky nezobrazí (`InboxView.swift:388-405`).
- Při startu aplikace se sync **nevolá vůbec** (`.task` ř.197-200).
- Backend sync (`POST /api/sync` → `resend_service.sync_emails()`, ř.245-287): limit 50 bez paginace, křehké přiřazení usera (neznámý alias → user 1). Tyto backend slabiny teď **neřešíme** (mimo rozsah), jen iOS stranu.

### C. Profil — dnešní stav
- `ProfileDetailView.swift:8-52` je read-only (username, email, odhlášení). Žádné editační pole.
- DB `users`: jen sloupec `from_name` (migrace 006), žádné `first_name`/`last_name`/`phone`.
- Neexistuje žádný update endpoint (`routes/settings.py` je prázdný) ani iOS update metoda.
- `from_name` se používá jako From hlavička (`resend_service.py:171`, přes `get_user_from_address`).
- Existující iOS formulářový pattern k napodobení: `ServerEditorView` (`SettingsView.swift:822-919`) a `ContactFormView` (`ContactsView.swift:189-232`).

## Navrhované změny

### A. Sent fix (iOS only)
- `APIClient.swift`: `emails(...)` získá nový parametr `direction: String? = nil`, přidá se do query.
- `InboxView.swift` `fetch()`: pokud `folderParam == "sent"`, poslat `direction=outbound`, jinak `inbound` (parita s webem `app.js:78-82`).

### B. Sync fix (iOS only)
- `InboxView.reload()`: synchronizaci **vyčkat** před fetchem — sloučit do jednoho `Task`: `await syncClient.syncEmails()` → poté `await fetch()`. Žádný detached task.
- `.task` při startu (ř.197): přidat volání sync (stejný sekvencní flow jako reload) — první spuštění aplikace stáhne nové maily.
- Chyba syncu nesmí zablokovat zobrazení listu: sync selhání → log/alert, fetch proběhne vždy.

### D. SSE push do iOS (live notifikace o novém e-mailu)
- Backend **nemění** — endpoint `GET /api/events` (`src/openmail/sse.py`) už existuje, auth via `session_id` cookie, broadcast `new_email` eventů (`notify` se volá při přijetí mailu), keepalive každých 15 s.
- **Nový soubor `ios/openMail/API/SSEClient.swift`:**
  - `URLSession` dataTask na `GET {baseURL}/api/events` (cookie pošle existující cookie jar automaticky),
  - vlastní parser SSE formátu (řádky `event:` / `data:` oddělené prázdným řádkem) — `EventSource` na iOS neexistuje nativně,
  - callback `onEvent: (String) -> Void`, konkrétně reaguje na `new_email`,
  - auto-reconnect: při ukončení spojení/expirovaném spojení zkusit znovu s backoffem (1 s → 2 s → 4 s … max 60 s), reset backoffu po úspěšném `connected` eventu,
  - stop při `clearSession` (odhlášení).
- **Napojení do `InboxView` (nebo App-scoped store):**
  - po přihlášení/restore session otevřít spojení,
  - na `new_email` event → spustit reload listu (stejný flow jako pull-to-refresh: sync + fetch),
  - na `scenePhase` změny: při `.active` otevřít/obnovit spojení, při `.background` zavřít (iOS ukončí socket na pozadí stejně),
  - po odhlášení zavřít.
- Fallback: když SSE spojení nefunguje (tunnel výpadek), aplikace funguje jako dnes — sync na start/refresh.

## Rizika

- Změna `get_user_from_address` ovlivní From hlavičku všech odchozích e-mailů — fallback řetěz zajišťuje, že bez vyplněných jmen se nic nezmění.
- iOS `User` decode: nová pole jako optional → starší backend/cache nerozbije.
- Migrace 007 je čisté ALTER TABLE ADD COLUMN — bez rizika dat.
- SSE skrze Cloudflare Tunnel: bufferování je ošetřené hlavičkou `X-Accel-Buffering: no` (backend posílá), idle timeout tunelu může spojení utínat — řeší auto-reconnect s backoffem.
- Více SSE spojení při rychlém přepínání obrazovek — klient musí držet jednu spojení per session (singleton), ne per view.
