# Plán: Composer Cancel + Add recipient inline + Version history rozsah (0.0.29)

**Stav:** čeká na schválení
**Návratový bod:** `Latest-Dev` HEAD `6068160` (0.0.28)
**Cílová verze:** 0.0.29 (MARKETING_VERSION 0.0.29, CURRENT_PROJECT_VERSION 28)

## Cíl

1. **Cancel v Composeru funguje** — tlačítko zavře Composer a vrátí se na předchozí obrazovku (Inbox).
2. **"Add recipient" na stejném řádku jako "To"** — v řádku Komu se zobrazuje nápis „To:“ a hned vedle něj (na stejném řádku, v jednom `HStack`u) placeholder `TextField`u.
3. **Version History v Settings** nezobrazuje 0.0.20 (a starší) v rozevíratelném seznamu.

## Problémy v současném kódu

### A. Cancel v Composeru
- `InboxView.swift:189-194` otevírá `ComposerView()` přes `NavigationLink` (push v NavigationStacku).
- `ComposerView.swift:111`: `ToolbarItem(placement: .topBarLeading) { Button("action.cancel") { dismiss() } }`.
- `dismiss()` uvnitř pushnutého view vrací `nil` (Composer není prezentovaný, je pushnutý). `@Environment(\.dismiss)` v takovém případě nic nezavře — je třeba použít `@Environment(\.dismiss)` **v kombinaci s `NavigationStack` uvnitř Composeru** (který tam je) a správným vyhodnocením kontextu. iOS 16+ standardně `dismiss()` u pushnutého view nepracuje — musí se řešit přes vlastní `@Environment(\.dismiss)` binding s `isModal`-přes `presentationMode` (deprecated), nebo přes `DismissAction`.
- Aktuálně `ComposerView` má vlastní `NavigationStack { ... }` (ř.73) — push v Inboxu vytvoří **dvojitý NavigationStack**: vnější z Inboxu + vnitřní z Composeru. `dismiss()` v toolbaru vnitřního stacku zavře **pouze vnitřní stack** (self-navigation), ale vnější `NavigationLink` zůstane aktivní. Proto se po kliknutí na Cancel nestane nic viditelného (prázdná vnitřní navigace se zavře, ale tlačítko zmizí spolu s `NavigationStack`em — výsledek: Composer stále „visí“ v Inboxu).

### B. "Add recipient" na stejném řádku jako "To"
- `ComposerView.swift:133-159` (`recipientRow`): `Text("composer.to")` je v `HStack(alignment: .top, spacing: 8)` jako samostatný sloupec, a pak `FlowLayout` s chips a `TextField` jako další sloupec. Výsledkem je, že „To:“ je nahoře vlevo a chips/input začíná **až pod ním** v dalším sloupci.
- Očekávané chování: „To:“ + placeholder `TextField` (a chips) na **jednom řádku** – `TextField` je v `HStack`u přímo napojený na „To:“ label.

### C. Version History zobrazuje 0.0.20
- `SettingsView.swift:266-316`: `changelogHistorySection` volá `updateService.mergedHistory()` a filtruje jen `currentVersion`. `update.json.history` aktuálně obsahuje 12 verzí (0.0.27, 0.0.25, 0.0.24, 0.0.23, 0.0.22, 0.0.21, 0.0.20, 0.0.19, 0.0.18, 0.0.17, 0.0.16, 0.0.15).
- Staré verze pod 0.0.21 jsou irelevantní — zobrazují se jen proto, že v manifestu zůstaly.
- Řešení: omezit `history` v manifestu na **posledních 6 verzí** (0.0.27–0.0.21). Starší verze (0.0.20 a níže) zůstanou jen v `bundledChangelogHistory` jako fallback pro staré buildy.

## Navrhované změny

### A. Composer Cancel funguje

`ios/openMail/Views/ComposerView.swift`:

1. **Odstranit vnitřní `NavigationStack`** na ř.73. `ComposerView` pak bude fungovat jako pushnutý view (s toolbar itemy vnějšího stacku) i jako tab v `MainTab` (s toolbar itemy root-level).
2. `@Environment(\.dismiss)` pak správně zavře vnější NavigationStack při pushnutí z Inboxu.
3. **Toolbar přesunout na úroveň view body** (ne uvnitř NavigationStack) – SwiftUI 16+ vyžaduje toolbar attachment pro správné chování.
4. **Zachovat `presentationDetents` a `navigationBarTitleDisplayMode`** na úrovni `.toolbar` modifieru (přes `ToolbarItem`).

Konkrétní diff:

```swift
var body: some View {
    VStack(spacing: 0) { ... }  // stávající obsah
    .background(Color(.systemBackground))
    .scrollDismissesKeyboard(.interactively)
    .navigationTitle("action.compose").navigationBarTitleDisplayMode(.inline)
    .toolbar {
        ToolbarItem(placement: .topBarLeading) { Button("action.cancel") { dismiss() } }
        ToolbarItem(placement: .topBarTrailing) { ... }
        ToolbarItemGroup(placement: .keyboard) { ... }
    }
    .task { ... }
    .fileImporter(...)
    .photosPicker(...)
    .onChange(of: photosPickerItems) { ... }
    .alert(...)
}
```

`ComposerView` se pak musí pushnout z Inboxu **bez** dalšího `NavigationStack`u. To už je splněno — Inbox ho pushuje jako `NavigationLink { ComposerView() }` (ř.189-194).

**Poznámka:** Composer je také v `MainTab.swift:13` jako samostatný tab. V tom případě běží v **kořenovém** kontextu `TabView` (žádný NavigationStack nad ním). `@Environment(\.dismiss)` bude `nil` a `Cancel` tlačítko bude deaktivované (nebo zobrazené s `.disabled(true)` pokud dismiss == nil). Toto je akceptovatelné chování – v tab režimu Cancel nedává smysl, protože Composer můžeš opustit jen přepnutím na jiný tab.

### B. "Add recipient" inline s "To"

`ComposerView.swift`, `recipientRow` (ř.133-159):

```swift
private var recipientRow: some View {
    HStack(alignment: .center, spacing: 8) {
        Text("composer.to")
            .foregroundStyle(Color(.secondaryLabel))
            .font(.system(size: 15))
            .frame(width: 38, alignment: .leading)
        FlowLayout(spacing: 6) {
            ForEach(recipients) { contact in
                chip(for: contact)
            }
            TextField("", text: $toInput, prompt: Text("composer.toPlaceholder").foregroundStyle(Color(.placeholderText)))
                .font(.system(size: 15))
                .textContentType(.emailAddress)
                .textInputAutocapitalization(.never)
                .autocorrectionDisabled(true)
                .keyboardType(.emailAddress)
                .frame(minWidth: 120)
        }
    }
    .padding(.horizontal, 16)
    .padding(.vertical, 8)
}
```

- `Text("composer.to")` se zobrazí vlevo, má fixní šířku 38 (zarovnání jako v subject/body řádcích).
- `FlowLayout` (chips + input) pokračuje hned za ním, wrapuje na další řádek když přesáhne.
- Zarovnání `center` (ne `top`) – `To` label bude vertikálně zarovnaný na střed prvního řádku chips.

## Rizika

- Odstranění vnitřního `NavigationStack`u může ovlivnit zobrazení navigačního title v Composeru, pokud je pushnutý vnořeně. Test: otevři z Inboxu (push) — title „Nová zpráva“ by měl být vidět (přebírá ho vnější stack). V tab režimu title nezobrazí (TabView root).
- V tab režimu `Cancel` tlačítko bude mít `dismiss == nil` — musí se to ošetřit `if let dismiss` nebo `.disabled(dismiss == nil)`. V `MainTab.swift` ř.13 je Composer vždy v tabu, takže tam Cancel nesmí být aktivní. Nejlepší řešení: `dismiss` v toolbaru podmínit: `if let dismiss { Button(...) { dismiss() } }` (v 0.0.29 tlačítko v tab režimu nebude vidět).
